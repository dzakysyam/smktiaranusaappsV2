# Kontrak integrasi DRAF v1 (adapter lokal SENTRA tersedia)
Status kode terbaru: pengirim outbox SENTRA memakai POST ke `HUMANIS_REPORT_URL` melalui HTTPS, bearer token dari OIDC client credentials (`reports:submit`), header `Idempotency-Key` dari UUID event dan menuntut JSON `acceptedVersion` sesuai versi laporan. Body saat ini `{sourceSystem:"SENTRA",reportId,version,summary}` tanpa periode; belum cocok dengan rancangan PUT berversi di bawah. Endpoint penerima Humanis baru hanya simulasi `TU_SIMULASI` dengan kunci lokal dan Map in-memory. Jangan mengonfigurasi URL ini sebagai integrasi produksi. Sebelum tes lintas repo, sepakati payload periode, sumber, issuer/audience/scope, receipt, persistensi, audit, dan callback keputusan. Respons flush `{ok:true}` tidak membuktikan seluruh event sukses; lihat `syncStatus` per laporan.

URL Humanis di bawah contoh rancangan. SENTRA menyediakan `POST /api/integration/decisions` dan `POST /api/integration/outbox` lokal; bentuknya belum sama persis dengan rancangan PUT berversi di bawah dan perlu diselaraskan sebelum integrasi. Humanis baru berada di repo dan deployment berbeda. Sumber tetap pemilik laporan resmi. Autentikasi antar backend melalui identitas layanan IdP standar yang disahkan IT, audience khusus, TLS, izin scope paling sempit; tidak menggunakan password pengguna atau token buatan sendiri.

1. TU -> Humanis: `PUT /api/v1/integrations/tu/reports/{reportId}/versions/{version}`; header `Idempotency-Key: UUID`, `Authorization: Bearer <access-token layanan>` (hanya spesifikasi, jangan masukkan nilai nyata). Body: `sourceSystem=tu`, `reportId`, `version`, `periodStart`, `periodEnd`, `status=submitted`, `summary` agregat minimal + definisi metrik, `evidenceRef` opaque opsional, `sourceUpdatedAt`, `detailHref` allowlist. Humanis unique (sourceSystem, reportId, version); body identik replay menghasilkan hasil identik; versi lama 409, payload berbeda untuk key sama 409. Respons `snapshotId`, `acceptedVersion`, `syncStatus=received`.
2. Kepala Sekolah POST di Humanis `POST /api/v1/reports/{snapshotId}/reviews` dengan `expectedVersion`, `action=approve|request_revision|feedback`, komentar opsional; hanya permission `reports.review` dan objek diizinkan. Hasil review tidak otomatis final pada sumber.
3. Humanis -> TU: `PUT /api/v1/integrations/humanis/decisions/{decisionId}` dengan Idempotency-Key dan body `reportId`, `version`, `action`, `reviewerSubject`, `decidedAt`, `feedback`. TU verifikasi audience/issuer/scope, versi/status cocok, catat keputusan+audit+inbox atomik; respons `sourceStatus`, `confirmedVersion`, `sourceDecisionId`.
4. Jika callback gagal, Humanis menampilkan `sync_failed`/`pending_confirmation` dan retry dengan backoff terbatas, tanpa mengaku status sudah sah. TU menolak revisi stale 409 dan replay identik 200 tanpa efek ganda. Job rekonsiliasi membaca `GET /api/v1/integrations/tu/reports/{id}/status` dengan autentikasi layanan.

Kebijakan retry, skema JSON rinci, masa retensi, format tanggal/timezone, serta izin detailHref perlu kesepakatan. Jangan memuat nama, NISN, bukti mentah, atau transaksi siswa dalam snapshot. Semua endpoint privat menegakkan sesi/izin server; rate limit dan audit.
