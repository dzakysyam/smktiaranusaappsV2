# Batas aplikasi dan rancangan integrasi

Stack akhir belum ditetapkan. SENTRA memakai Node.js, Next.js, TypeScript, Prisma, PostgreSQL secara sementara atas arahan pemilik: `architecture.md` repo Humanis baru mengutip proposal v1.1 sebagai Node.js LTS + Next.js + Prisma + PostgreSQL + Nginx, tetapi proposal/SRS asli tidak ada di clone. Jangan menyamakan implementasi Humanis baru dengan stack final semua bidang. Pilihan deployment, runtime PHP sementara, DB tiap domain dan IdP menunggu tim IT.

- Epoint, Presta, Riasec, SPMB, Eraport: pemilik transaksi dan data masing-masing. TU: pemilik surat/disposisi/arsip dan ledger keuangan bila disetujui. Humanis baru: portal identitas dan izin portal, ringkasan laporan, review, status integrasi. Humanis PHP lama tetap referensi hingga keputusan migrasi.
- IdP standar OIDC menyediakan Authorization Code + PKCE; setiap backend aplikasi memvalidasi issuer, audience/client ID, signature melalui JWKS, nonce/state, expiry, sesi aplikasi dengan cookie aman dan RBAC lokal. Jangan pass password antar aplikasi atau menerima cookie lintas domain tanpa rancangan; redirect deep link hanya ke allowlist internal dan relatif. Humanis internal login sekarang bukan OIDC. Pilihan IdP dan domain/redirect URI disahkan IT.
- Rute publik tetap publik bila disahkan. Semua halaman privat, API, file, dan ekspor butuh validasi sesi + izin backend. Cutover login per aplikasi setelah paritas, log/audit, rollback dan persetujuan owner.
- TU membuat laporan resmi dan snapshot outbox dalam transaksi lokal. Pengirim retry terbatas POST ke Humanis dengan identitas layanan terverifikasi (misalnya OAuth2 client credentials via IdP yang mendukung), idempotency key dan versi. Humanis menyimpan snapshot metadata, bukan detail transaksi. Review tersimpan di Humanis, callback keputusan terautentikasi masuk inbox TU; TU cocokkan versi, simpan keputusan dan audit secara atomik, balas status/versi; Humanis tandai confirmed atau sync_failed jika gagal. Anti-replay, retry/backoff dan rekonsiliasi berkala wajib.
- Akun manusia dan akun layanan berbeda; dua aplikasi punya basis data dan deployment terpisah. Referensi bukti adalah ID opaque yang hanya diresolusi oleh backend sumber setelah izin, bukan URL publik atau dokumen pribadi. Tidak menyisipkan nama/NISN siswa di snapshot umum.

Status integrasi: SENTRA memiliki endpoint lokal dan adapter kontrak di `sentra-tu/`, tetapi tidak ada integrasi dua deployment Humanis dan TU yang hidup. Periksa `sentra-tu/README.md` untuk verifikasi.
